# хелпи

Мини-приложение MAX для подбора волонтёрских дел. Человек выбирает интересы, оценивает шесть карточек, указывает возраст и получает рекомендации. Дело можно открыть на ДОБРО.РФ, сохранить в личный план или пригласить друга. Завершённые визиты выращивают личный сад.

## Запуск для проверки

Нужен Docker Engine с Compose v2. Токены, Node и файл `.env` для демо не нужны.

```bash
docker compose up -d --build
```

Открыть [localhost:3210](http://localhost:3210). Проверка сервиса: [localhost:3210/api/health](http://localhost:3210/api/health). Первый запуск создаёт БД, применяет миграции и добавляет тестовые данные.

## Состав

- `app`: Node.js 24, HTTP API и собранный React-интерфейс. MAX Bridge передаёт подписанные данные запуска.
- `worker`: обновление каталога и очередь разметки; в демо — только служебные проверки и удаление истёкшей геопозиции.
- `postgres`: PostgreSQL 17, общий каталог, профили, реакции и планы.
- Рекомендатель, планы и реакции общие для мини-приложения и ежедневной подборки бота. В боте нет команд планов, карты и поиска.

Интерфейс: React 19, Vite, MapLibre, Three.js / React Three Fiber. Версии библиотек зафиксированы в `package-lock.json`. Dockerfile многостадийный; приложение и worker работают от пользователя `node`. Миграции лежат в `server/migrations`, контракт API — в `docs/openapi.yaml`.

## Окружение и порты

Все параметры перечислены в `.env.example`. Значения по умолчанию предназначены только для локального демо.

| Параметры | Назначение |
| --- | --- |
| `APP_PORT=3210`, `POSTGRES_PORT=54329` | Порты на хосте, привязаны к 127.0.0.1 |
| `DOCKER_DEMO_MODE=true`, `DEMO_DATA=true` | Cookie-профиль и синтетический каталог |
| `POSTGRES_ADMIN_PASSWORD`, `POSTGRES_APP_PASSWORD` | Разные пароли администратора и ограниченного пользователя БД |
| `DATABASE_URL`, `DB_SCHEMA=app`, `DB_POOL_SIZE=10` | Подключение при запуске Node вне Docker; внутри Compose URL собирается автоматически |
| `MAX_BOT_TOKEN`, `MAX_BOT_USERNAME`, `MAX_MINI_APP_URL` | Обязательны только для production MAX |
| `MAX_WEBHOOK_URL`, `MAX_WEBHOOK_SECRET` | HTTPS webhook; polling включается отдельно через `MAX_POLLING` |
| `PRIVATE_DATA_ENCRYPTION_KEY_FILE`, `DB_TLS_CA_FILE` | Файлы ключа шифрования и CA PostgreSQL для production |
| `CATALOG_SYNC_ENABLED`, `ANNOTATION_ENABLED`, `LLM_API_KEY`, `LLM_BASE_URL` | Импорт и фоновая разметка; в демо внешние вызовы заблокированы |
| `RECOMMENDATION_V2_ENABLED` | Откат на прежнее ранжирование без удаления данных |
| `APP_IMAGE`, `APP_COMMIT` | Готовый образ и версия сборки |

Внутри Docker: API — 3210, PostgreSQL — 5432. Worker порта не открывает. Production-конфигурация с HTTPS-прокси — `compose.production.yaml`; подготовка TLS и ключей описана в `docs/OPERATIONS.md`.

## Данные

PostgreSQL хранит данные в volume `postgres-data`. В production имена, профили, личные планы, реакции и координаты шифруются AES-256-GCM; ключ хранится отдельно от БД и образа. Соединение с PostgreSQL проверяет сертификат частного CA, пароли используют SCRAM. Новый кластер создаётся с checksums. Проверка подписи MAX выполняется на сервере; изменять и завершать план может только владелец.

Геопозиция добровольная, действует 24 часа и удаляется по сроку или запросу. Расстояние — по прямой, не маршрут. Удаление аккаунта удаляет его профиль, планы, участия, реакции и координаты. Флаг пояснения сада хранится в отдельном столбце и не сбрасывается сохранением настроек.

В production используются публичные дела ДОБРО.РФ и сохранённая разметка. Открытие ленты не вызывает LLM. Фоновая разметка использует Responses API, строгую JSON-схему и `store=false`; по умолчанию отключена. MAX Bot API отправляет приглашения с картинкой настоящего дела и ежедневную подборку.

## Тестовые данные

`data/demo-themes.json` задаёт 14 тем. На первом запуске создаются 672 карточки четырёх городов с местными изображениями. Даты отсчитываются от сохранённой даты первого запуска и не сдвигаются при перезапуске; тестовый каталог действует год. Названия помечены `[Тест]`, разметка синтетическая.

Каждый новый демопрофиль получает один тестовый согласованный план с прошедшей датой, без выполнения. У него нет реального организатора. Он нужен только для проверки завершения и сада. Повторный вход не создаёт новый план. Создание таких записей при `DEMO_MODE=false` запрещено; production-каталог их не показывает.

## Сценарий проверки

1. Открыть приложение в новом профиле браузера. Выбрать интересы → «Настроить ленту» → оценить шесть карточек. Возраст спрашивается отдельным окном на ленте.
2. Указать 23 года. Появляются рекомендации. Прокрутить «Все дела» до конца: карточки догружаются по 12 без повторов; смена фильтра сбрасывает лимит.
3. Открыть карточку. «Записаться на дело» открывает ДОБРО.РФ (для тестовых карточек — главную). «Сохранить дело» создаёт один личный план; повторное нажатие не создаёт второй.
4. Открыть «Профиль». В саду счётчик 0 и два декоративных дерева, ручных кнопок изменения нет. Закрыть пояснение через «Посмотреть сад» или Escape. После перезагрузки оно не возвращается.
5. Раскрыть «Мои планы» → тестовое дело → «Открыть план». Указать часы и впечатление в разделе «Как всё прошло?». Счётчик становится 1, появляется растение. Повторное выполнение и отмена другого плана не добавляют награды.
6. Перезапустить `app` и `worker`: планы, выполненные дела и закрытое пояснение сохраняются. В светлой и тёмной теме окно читается, на ширине 430 px кнопки доступны.
7. Открыть `/api/health`: `ok=true`, `mode=demo`, БД доступна и heartbeat worker обновляется.

Автоматические проверки без MAX и LLM:

```bash
npm ci
npm test
```

Тесты не входят в runtime-образ; для них нужен Node.js 24. Полный демосценарий API против запущенного Docker: `npm run test:demo`. Браузерный сценарий: `npx playwright install chromium`, затем `npm run test:ui`. Интеграционные PostgreSQL-тесты используют отдельную БД с именем, содержащим `test`; параметры и команды — в `docs/OPERATIONS.md`.

## Ограничения

- Локально работают интерфейс, API, рекомендации, личные планы и сад. Приглашения с пересылкой, запрос геопозиции через бот и ежедневные сообщения проверяются внутри MAX с production-настройками.
- Выполнение — самоотчёт. Сохранение плана не регистрирует на ДОБРО.РФ и не подтверждает волонтёрские часы. Сначала нужно согласовать участие с организатором.
- Без возраста не показываются дела с возрастным ограничением. В production доступны только активные вакансии с актуальной разметкой.
- Бот отправляет одну подборку в день после `/start`; `/stop` отключает её. Окно отправки — 09:00–11:00 по Москве. Автоматического обучения на сходстве пользователей нет.
- Сад требует WebGL; карта требует интернет для картографических тайлов. В первый вход 3D-модели загружаются отдельно.
- Два стартовых дерева — декорация, не выполненные дела и не награда. Файлы ресурсов и лицензии находятся в `public/garden-assets`.

## Остановка и повторный запуск

```bash
docker compose down
docker compose up -d
```

Volume остаётся на месте. `docker compose restart app worker` перезапускает только сервисы. Полный сброс **тестовой** БД: `docker compose down -v` (удаляет все её данные). Не выполнять эту команду в production.
