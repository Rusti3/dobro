# Первый шаг

Самостоятельная альтернатива афише «Рядом»: Telegram-бот и Mini App для взрослого новичка, который хочет помогать, но откладывает первый визит. Результат — выбранное дело, сообщение организатору, согласованный личный план и возможность пойти со знакомым человеком.

**Это отдельный проект.** Код и конфигурация `../sdfa` не изменяются. По запросу реализован Telegram, а не MAX. Для допуска по исходному конкурсному PDF понадобится адаптер MAX, доступное развёртывание и презентация; текущая версия не объявляется готовой конкурсной заявкой.

## Запуск

Node.js 24+:

```sh
npm ci
npm run dev
```

Открыть http://127.0.0.1:3210. По умолчанию это подписанный в интерфейсе локальный деморежим без токенов. Каждый браузер получает отдельную случайную HttpOnly-сессию, данные сохраняются в SQLite. Для второго пользователя открой ссылку приглашения в другом браузере или приватном окне.

Все локальные компоненты одной командой:

```sh
docker compose up --build -d
```

Порт `3210` доступен только на localhost; SQLite сохраняется в Docker volume `first-step-data`. Остановка: `docker compose down`. Повторный запуск: `docker compose up -d`. Удаление volume через `down -v` удаляет данные — для обычной остановки не нужно. Сборка рассчитана на один небольшой Node-контейнер, без БД-сервера. Docker daemon в среде разработки не был запущен: фактическая контейнерная сборка требует отдельной проверки.

Production-сборка без Docker:

```sh
npm run build
npm start
```

## Что работает

- Онбординг: интерес и главный барьер → предпочтения сохраняются на сервере.
- Подборка шести реальных карточек ДОБРО, фильтры, поиск, исключение завершённых программ по текущей дате.
- Понятные первые действия, сохранённый оригинал описания, адрес, период, дата выгрузки и ссылка на источник.
- Шаблон первого сообщения; пользователь сам отправляет его организатору.
- Личный план: чек-лист, согласованная дата в московском часовом поясе, место встречи, отмена без штрафа, выгрузка `.ics`.
- Приватное приглашение на семь дней; второй участник принимает его и получает доступ к плану. До четырёх человек, отзыв ссылок, выход участника. Это действующие серверные механики, не нарисованные аватары.
- Личный сад: намерение → согласование → впечатление после визита. Завершение — самоотчёт автора, без официальных часов и баллов.
- Удаление профиля, планов и участия в чужих компаниях.
- Telegram SDK, HMAC-проверка initData на сервере, бот с `/start`, `/plan`, `/help`, `/stop`, `/delete`, одно напоминание перед визитом по согласию.

## Подключить отдельного Telegram-бота

1. Создать **нового** бота через BotFather. Токен существующего проекта не копировать.
2. Развернуть постоянный Node-сервис с постоянным диском и HTTPS. Этот сервер использует long polling и не предназначен для бессерверных функций Vercel.
3. Скопировать `.env.example` в `.env`; установить `DEMO_MODE=false`, `TELEGRAM_BOT_TOKEN`, `BOT_USERNAME` без `@`, `MINI_APP_URL` без завершающего `/`.
4. `npm run bot:setup` — установит команды и кнопку меню, отключит webhook этого бота для long polling. Скрипт вызывает Telegram API и предназначен только для выбранного нового бота.
5. Запустить **один** экземпляр `npm start`, открыть бота и отправить `/start`. Открыть Mini App из кнопки бота. В BotFather при желании настроить Main Mini App.
6. В настройках Mini App включить напоминания. Команда `/start` нужна для доступного личного чата; без неё напоминание не отправляется.

Без токена и публичного HTTPS невозможно проверить реальную доставку Telegram-сообщений. Она не была выполнена в локальной демонстрации. Никакие сообщения от имени пользователя организаторам не отправляются автоматически.

| Переменная | Значение |
|---|---|
| `PORT` | `3210` |
| `HOST` | `127.0.0.1` локально, `0.0.0.0` внутри контейнера |
| `DB_PATH` | `./var/app.sqlite`; постоянный диск обязателен |
| `DEMO_MODE` | `true` локально; строго `false` для Telegram |
| `TELEGRAM_BOT_TOKEN` | Секрет только на сервере |
| `BOT_USERNAME` | Имя нового бота для ссылок приглашений |
| `MINI_APP_URL` | Публичный HTTPS origin Mini App |

## Проверить сценарий за 5 минут

1. Главная → «Найти свой первый шаг» → «Животные» → «Не хочется идти одному» → подборка.
2. «Помочь кошкам найти дом» → прочитать, что подтверждено источником → скопировать первое сообщение → открыть контакты ДОБРО. Внешнюю заявку проверяющий не обязан отправлять.
3. «Это мой первый шаг» → появляется личный черновик. Это **не** регистрация у организатора.
4. Отметить чек-лист; выбрать будущую дату в периоде программы, место и отметку согласования. Для демонстрации вводится тестовая договорённость, не реальная запись.
5. «Пригласить друга» → открыть ссылку в приватном окне → «Пойду вместе». После перезагрузки первого окна автор видит участника, друг видит общий план. Друг не может менять план автора.
6. Экспортировать календарь, перезапустить сервер — данные остаются. Отозвать приглашение — старая ссылка больше не работает.
7. Отменить план — сад не штрафует. После **наступления** согласованной даты автор может отметить впечатление. API-тест использует отдельную прошедшую дату для воспроизводимой проверки этого этапа.
8. Настройки → удалить данные. Созданные планы и приглашения удаляются; участие в других планах снимается.

## Архитектура и данные

`React → same-origin Node HTTP API → SQLite`. Тот же Node-процесс принимает обновления Telegram и отправляет напоминания. SDK служит мостом оболочки; доверие к личности строится только на проверенном `initData`, не `initDataUnsafe`.

`src/` — UI, `server/domain.js` — правила и HMAC, `server/store.js` — SQLite, `server/index.js` — авторизация и API, `server/telegram.js` — Telegram-адаптер, `data/catalog.json` — автономная подборка, `public/images/` — изображения из поставки.

Первичный источник: `../afisha-2026-09-09-delivery/events.jsonl`, исходные описания сверены с `raw/dobro-detail.jsonl`. В raw 2144 записи. Импортирована редакционная подборка **6 московских программ**, а не весь каталог: приоритет понятной точки входа. Импорт: `npm run catalog:import`. После обновления каталога перезапустить сервер. Для обычного запуска исходная поставка не нужна: JSON и изображения уже внутри проекта.

Короткие заголовки, причины выбора и советы — редакционная обработка, не новые факты организатора. Нет подтверждённых смен, брони, свободных мест, наставников, длительности и возрастных ограничений. Неизвестные поля показаны как «уточнить». Школа для детей и прошедшие панно не попали в пилот для взрослых. Период программы нельзя интерпретировать как ежедневный приём.

Зависимости закреплены в `package-lock.json`. Runtime production — Node 24 со встроенной SQLite. Внешние сервисы: Telegram Bot API, ДОБРО как внешний путь регистрации, Google Fonts для оформления (при недоступности — локальный sans-serif). Фото локальные, геокодер/LLM/платёжный сервис не нужны. Импорт не означает право на независимое коммерческое переиспользование фотографий: условия источника проверить перед публичным тиражированием.

## Проверки

```sh
npm test
npm run build
# При работающем npm run dev и установленном Microsoft Edge:
node scripts/visual-qa.mjs
```

Тесты проверяют HMAC, просроченные сессии, период события, запрет преждевременного завершения, приглашения между двумя пользователями, права доступа, перезапуск, отзыв ссылки и удаление. Браузерный сценарий проверяет мобильную навигацию, онбординг, карточку, план и принятие приглашения. Скриншоты находятся в `test-results/` (не включаются в Docker).

## Границы и эксплуатация

- Обновления общего плана видны после перезагрузки; live-chat и real-time push не реализованы.
- Дата визита и подтверждение — запись со слов автора. Нет интеграции заявок и посещаемости с ДОБРО.
- Сад — личный самоотчёт, не официальные часы или верифицированный эффект.
- Встречи с проверенными наставниками, модерация и смены организаций — план пилота, не функции этой версии.
- SQLite и один worker подходят для небольшого пилота. Для нескольких экземпляров нужны PostgreSQL, очередь напоминаний и отдельный бот-worker.
- При повторной доставке обновления Telegram возможен повтор ответа в узком окне сетевого сбоя; необходим transactional outbox для строгой идемпотентности отправки. Секреты не логируются.
- Проверка initData ограничена одним часом; после истечения приложение предложит открыть его заново.
- Нет утверждения об измеренном улучшении конверсии: эффект — проверяемая гипотеза.
